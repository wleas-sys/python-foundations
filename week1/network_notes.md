# 计算机网络笔记

## 2026-11-05：TCP/IP 分层与封装

### 层次与常见协议

| 层次 | 常见协议 | 主要职责 |
|---|---|---|
| 应用层 | HTTP、DNS | 定义应用之间交换什么数据 |
| 传输层 | TCP、UDP | 端到端传输、可靠性和端口寻址 |
| 网络层 | IP | 跨网络寻址和路由 |
| 数据链路层 | Ethernet、Wi-Fi | 同一链路内的帧传输和差错检测 |
| 物理层 | 电信号、光信号、无线电 | 传输比特 |

### PDU

PDU 表示“协议数据单元”：

| 层次 | PDU |
|---|---|
| 应用层 | 报文/message |
| 传输层 | TCP 为段 segment；UDP 通常称数据报 datagram |
| 网络层 | 分组/数据报 packet/datagram |
| 数据链路层 | 帧 frame |
| 物理层 | 比特 bit |

### 封装

发送方从应用层向下传递时，每层添加上该层需要的控制信息：

```text
HTTP 报文
→ 传输层添加 TCP 头，形成 TCP 段
→ 网络层添加 IP 头，形成 IP 分组
→ 数据链路层添加帧头和帧尾，形成以太网帧
→ 物理层转换为比特发送
```

接收方反向处理，逐层读取并移除控制信息，称为解封装。

### 关键理解

- 下层为上层提供数据传输服务。
- 上层不知道下层具体如何实现。
- 封装使每一层只关心自己负责的信息。
- IP 负责主机到主机的寻址和路由。
- TCP/UDP 使用端口区分同一主机上的不同应用。
- MAC 地址主要用于同一链路内的帧传递。

### 待复习

- TCP 段头包含哪些字段。
- IP 头中的源地址和目标地址。
- 以太网帧头中的源 MAC 和目的 MAC。
- 路由器和交换机分别主要处理哪一层。

### 路由器和交换机

| 设备 | 主要工作层 | 主要转发依据 |
|---|---|---|
| 交换机 | 数据链路层 | 目的 MAC 地址 |
| 路由器 | 网络层 | 目的 IP 地址 |

交换机通常用于同一局域网内部转发帧，并根据源 MAC 地址学习 MAC 地址表。

路由器连接不同网络，根据目的 IP 地址和路由表选择下一跳。通常每经过一个路由器，TTL 会减 1，IP 头校验和也会重新计算；数据链路层帧会被重新封装。

### 同一网段与跨网段

同一网段内，主机 A 直接发送给主机 B：

```text
IP 目的地址：B 的 IP
帧目的 MAC：B 的 MAC
```

跨网段时：

```text
IP 目的地址：B 的 IP
帧目的 MAC：默认网关的 MAC
```

记忆规则：

- IP 地址负责端到端寻址。
- MAC 地址负责当前链路上的逐跳交付。
- 普通路由转发通常只改变 TTL 和链路层帧，不改变最终目的 IP。
- NAT 场景可能修改 IP 地址和端口。

### MAC、IP 与端口

| 标识 | 主要作用 |
|---|---|
| MAC 地址 | 在当前链路中把帧交给正确的网卡 |
| IP 地址 | 把分组交付到目标主机 |
| 端口号 | 把传输层数据交给目标主机上的具体应用进程 |

同一台电脑同时运行浏览器和游戏时，数据先由 MAC 地址送达本机网卡，再由 IP 协议字段区分 TCP/UDP，最后由传输层目的端口交给对应应用。

常见服务端口：

- HTTP：80
- HTTPS：443
- SSH：22
- DNS：53

### DNS

DNS 负责把域名转换为 IP 地址，例如：

```text
www.example.com → 93.184.216.34
```

DNS 是应用层协议，默认使用 53 端口：

- 普通短查询通常使用 UDP 53。
- 响应过大、响应被截断或进行区域传送时使用 TCP 53。

因此不能只记成“DNS 等于 UDP”：DNS 默认优先使用 UDP，但需要时也会使用 TCP。

### TCP 三次握手

TCP 建立连接需要交换三次控制报文：

```text
1. 客户端 → 服务器：SYN，携带客户端初始序号
2. 服务器 → 客户端：SYN + ACK，携带服务器初始序号，并确认客户端序号
3. 客户端 → 服务器：ACK，确认服务器序号
```

简化表示：

```text
SYN
SYN + ACK
ACK
```

三次握手的作用：

- 确认双方都能发送和接收数据。
- 同步双方初始序列号。
- 为可靠传输建立连接状态。

注意：握手报文是 TCP 段，不是“比特”。“比特”是物理层传输的数据单位。

### TCP 序列号

TCP 把应用数据看作连续字节流，并给字节编号。

主要作用：

1. 接收方按序号恢复正确顺序。
2. 发现序号缺口，从而判断数据丢失。
3. 识别重复到达的数据。
4. ACK 可以确认已经按顺序收到哪些字节。
5. 支持丢失数据重传。

不要把地址和序列号混淆：

- IP 地址：找到目标主机。
- 端口号：找到目标应用。
- TCP 序号：定位字节流中的位置。
- ACK 号：表示接下来期望收到的序号。
